# Research: Free deployment options in 2026 for a low-traffic React/Vite SPA + `/api` backend

## Summary
For a small Spanish-language tutoring app with likely commercial use, **Cloudflare Pages** is the best free frontend default: generous static hosting, custom domains, automatic SPA fallback, and a clean path to add `/api` with Pages Functions/Workers + D1. **Netlify** is the easiest alternative when you specifically need an external `/api` proxy rule, but its 2026 free plan is credit-capped. Avoid **Vercel Hobby** and **GitHub Pages** for a production tutoring business because both have explicit commercial-use restrictions/caveats.

### Practical recommendation for TuEstudio / tutoring app

1. **Use Cloudflare Pages for the React/Vite SPA** with `npm run build` and `dist`. It gives the cleanest free production posture: generous limits, custom domain, automatic SPA fallback, and no obvious non-commercial restriction in the official Pages docs. [Cloudflare Pages limits](https://developers.cloudflare.com/pages/platform/limits/)
2. **Put `/api` on Cloudflare Workers/Pages Functions first** if backend needs are modest: contact forms, class inquiries, public tutor/course listings, booking requests, and admin-only CRUD. Pair with **D1** for simple relational data. [Workers limits](https://developers.cloudflare.com/workers/platform/limits/), [D1 pricing](https://developers.cloudflare.com/d1/platform/pricing/)
3. If the backend needs richer Postgres/Auth quickly, choose **Supabase** behind the API, but expect to upgrade once the app is real because free projects pause after inactivity. [Supabase pricing](https://supabase.com/pricing)
4. If you need a separate external REST API and want path proxying without writing an edge function, **Netlify** is the best static-host alternative because `/api/* https://api.example.com/:splat 200` is officially supported. [Netlify rewrites/proxies](https://docs.netlify.com/manage/routing/redirects/rewrites-proxies/)
5. **Do not choose GitHub Pages or Vercel Hobby** for a paid tutoring production site: GitHub Pages disallows using it as free hosting for online business/SaaS-like use, and Vercel Hobby is non-commercial. [GitHub Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits), [Vercel Hobby](https://vercel.com/docs/plans/hobby)

### Implementation notes

- For Vite, any `VITE_*` value is bundled into client code; never put secrets there. Use server-side env vars in Workers/Functions for API keys, mail provider credentials, payment keys, etc. [Vite env docs](https://vite.dev/guide/env-and-mode)
- On Cloudflare Pages, do **not** rely on `_redirects` to proxy `/api` to an external domain; Cloudflare documents proxying as relative-URL only. Use a Pages Function/Worker proxy or expose the backend with CORS. [Cloudflare redirects](https://developers.cloudflare.com/pages/configuration/redirects/)
- For a Spanish-language tutoring app, keep frontend hosting and DNS simple: `tuestudio.com` for SPA, `/api/*` for backend, and optionally `admin.tuestudio.com` later if the admin app grows.

- Free-tier terms can change quickly, especially Netlify credits and Vercel/Render limits; verify pricing pages again immediately before launch.
